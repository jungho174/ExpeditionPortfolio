# 프로젝트 개요

2026-11-10 현재: WhiteCastle 성문은 탐험 중부터 보이는 골렘 2마리 묶음 조우다. 정식 아군은 마법사 한 명이며 여러 아군 → 여러 적의 턴 구조를 지원한다. 적 HP는 개별 머리 위 바, 아군 HP는 우측 하단 패널로 표시한다. 구성 변경과 확장 범위는 [다수 적 조우](grouped-encounters.md)를 참조한다.

시연용 환경으로 `ExpeditionPortfolio/Maps/L_WhiteCastle`을 추가했다. 다리의 골렘 조우를 승리한 뒤 성문을 통과해 열린 안뜰에 도착한다. 보스는 이후 추가할 예정이며 현재는 전투 공간과 배치 참고점만 준비했다. 실행·편집 방법은 [WhiteCastle 맵](white-castle-map.md)을 참조한다.

현재 캐릭터·골렘 콘텐츠, 공통 아이템·턴 규칙, 기술별 카메라와 HP 식별자 설정의 소유권은 [공통 규칙과 캐릭터 콘텐츠](shared-combat-ownership.md)에 정리했다.

## 프로젝트 목적

`ExpeditionPortfolio`는 신입 Unreal Engine 클라이언트 개발자 포트폴리오를 목적으로 하는 싱글 플레이 3인칭 RPG 프로젝트다. 《Clair Obscur: Expedition 33》의 턴제 명령 전투와 실시간 방어가 결합된 감각을 참고하되, 제한된 Vertical Slice 안에서 전투 상태 관리, 입력 처리, 데이터 주도 설계, UI 연동과 디버깅 역량을 명확히 보여주는 것을 목표로 한다.

현재 기준선은 Unreal Engine 5.8 Third Person C++ 템플릿이다. 최소 조우, 전투 State Machine, HP/피해, 플레이어 명령, HUD와 실시간 패링/회피 판정이 구현돼 있다. 적 단일 타격 패턴은 Data Asset에서 피해량과 시간을 정의하며 가중치로 선택한다. 플레이어는 일반/강한 마법 Montage와 Niagara를 설정 데이터로 연결한다. 적은 AS_Spell_Cast_Attack의 타격 Notify를 기준으로 방어 구간을 열며, 타격 시 결과를 적용하고 모션 완료 후 다음 턴으로 넘어간다. 방어 시간·패링 시간·타격 보정은 PIE 중 수정하여 다음 적 공격부터 확인할 수 있다. 신호와 판정은 C++에서 검증하며 적응형 패턴 선택과 사운드는 후속 작업이다.

## 핵심 게임 루프

패링 성공은 섬광·타격음·약한 카메라 흔들림과 실제 0.15초의 슬로모션 후 짧은 마법 반격으로 이어진다. 원래 속도로 복귀한 뒤 발사체가 적에게 도착할 때 피해와 피격 모션을 적용하며 반격이 끝난 뒤 다음 턴이나 승리로 진행한다. 전용 설정은 `DA_ParryCounter`에서 조절한다.

전투 진입 시 서로 마주보게 정렬하고 숄더뷰로 전환한다. 강한 마법은 정면 준비 구도와 마름모 타이밍 게이지를 사용하며, 마지막 성공 구간의 Space 입력으로 피해 보너스를 얻는다. 공격·적 턴 구도 전환과 탐험 카메라 복귀를 전투 상태/행동 단계에 연결한다. 설정은 `docs/battle-camera-and-timing.md`를 참조한다.

플레이어 명령 HUD는 캐릭터 옆 기울어진 아이템/기술/공격 메뉴다. 기술에는 약한/강한 마법을 유지하고 공격은 맨손 근접 1회, 아이템은 전투당 제한 수량의 HP 물약을 사용한다. 약한 마법은 왼손 발사 → 적 몸통까지 비행 → 도착 시 폭발·피해로 분리했으며 비행과 모션 완료 후 다음 턴으로 진행한다. 별도 MP/AP 비용은 아직 없으며 물약용 영구 인벤토리도 포함하지 않는다. 설정 방법은 `docs/combat-command-menu.md`, `docs/player-magic-projectile.md`를 참조한다.

1. 플레이어가 3인칭 시점으로 필드를 탐험한다.
2. 필드의 몬스터와 조우하면 탐험 입력을 잠그고 턴제 전투로 전환한다.
3. 플레이어 턴에 공격 또는 스킬을 선택하고 대상과 행동을 확정한다.
4. 적 턴에는 공격 예고를 읽고 실시간으로 회피하거나 패링한다.
5. 치명타에서 승패를 확정하고 슬로모션·정지 후 결과창을 표시한다. 승리 확인은 남은 HP로 필드 복귀, 패배는 진입 HP로 재도전 또는 조우 바깥 후퇴를 선택한다. HP는 같은 실행 중 맵 전환·캐릭터 재생성 후에도 유지한다. 상세 설정은 `docs/battle-results.md`를 참조한다.

## 초기 Vertical Slice 범위

- 짧은 탐험 구간과 하나의 전투 조우 지점
- 플레이어 캐릭터 1명과 몬스터 1종
- 기본 공격 1개와 대표 스킬 1개
- 적 공격 패턴 1~2개와 식별 가능한 Telegraph
- 적 턴의 회피 및 패링 입력 창
- HP, 현재 턴, 명령 선택, 방어 결과를 표시하는 최소 HUD
- 전투 진입, 승리, 필드 복귀까지 이어지는 완결된 한 사이클
- 핵심 상태 전이와 피해/방어 판정을 검증할 자동화 또는 기능 테스트

## 초기 범위에서 구현하지 않을 기능

- 3인 파티 편성 및 캐릭터 교체
- 다수의 동시 적과 복잡한 행동 순서 시스템
- 오픈 월드, 퀘스트, 대화, 상점, 제작
- 장비 파밍, 대규모 스킬 트리, 영구 성장 시스템
- 저장/불러오기와 다중 세이브 슬롯
- 네트워크 멀티플레이 및 서버 권한 구조
- 완성형 접근성 메뉴, 다국어 현지화, 플랫폼별 배포
- 원작의 캐릭터, 로고, 음원, 모델 또는 연출을 그대로 복제하는 작업

## 포트폴리오에서 보여줄 기술 요소

- 명시적인 전투 State Machine과 안전한 상태 전이
- 탐험과 전투의 입력 모드 및 책임 분리
- C++ 핵심 로직과 Blueprint 연출 계층의 협업 구조
- `UActorComponent` 기반 전투 참가자 능력 분리 방향
- `UPrimaryDataAsset` 또는 `UDataAsset` 기반 스킬 및 적 패턴 정의
- Enhanced Input을 이용한 상황별 입력 활성화
- Delegate/Event 기반 UI 갱신과 불필요한 `Tick` 제거
- Animation Montage, Anim Notify, VFX/SFX를 판정 로직과 동기화하는 방식
- 디버그 로그, 상태 시각화, 자동화 테스트와 재현 가능한 빌드 검증
