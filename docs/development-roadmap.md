## 진행 원칙

- 각 마일스톤은 1~2주 단위로 완료 가능한 플레이 가능한 결과를 만든다.
- 1차 목표는 플레이어 1명과 몬스터 1종으로 전투 진입부터 종료까지 도는 최소 전투 루프다.
- 기능마다 C++ 핵심 로직, Blueprint 연결 지점, 검증 방법을 함께 정의한다.
- 다음 단계로 넘어가기 전에 `ExpeditionPortfolioEditor Win64 Development` 빌드와 해당 단계의 테스트를 통과한다.

## Milestone 1 — 최소 전투 골격 (1~2주)

목표: 플레이어 1명과 몬스터 1종이 번갈아 행동하고 승패가 결정되는 최소 전투 루프를 만든다.

- 전투 상태 enum과 전이 규칙 구현
- 전투 참가자 등록 및 최소 HP/피해 모델 구현
- 필드 조우에서 `BattleIntro` 진입
- 플레이어 기본 공격 1개와 적 기본 공격 1개
- `TurnEnd`, `Victory`, `Defeat`, `ReturnToField` 연결
- 개발용 로그 또는 Debug UI로 현재 상태 확인
- 정상 흐름과 잘못된 상태 전이 테스트

완료 기준: 한 번의 조우에서 양측이 턴을 교대하고, 승리 후 필드로 복귀할 수 있다.

## Milestone 2 — 플레이어 명령과 최소 UI (1주)

목표: 플레이어가 UI에서 공격 또는 스킬을 선택하고 전투 로직이 명령을 검증하도록 한다.

- `PlayerCommand` 입력 Context 분리
- 공격 및 대표 스킬 1개 선택 UI
- UI 명령 전달과 상태 Event 구독
- HP, 현재 턴, 선택 가능 Action 표시
- 잘못된 입력과 중복 확정 방지

완료 기준: UI가 상태를 소유하지 않은 채 명령 선택과 전투 정보 표시를 수행한다.

`BasicAttack`, 전투당 1회의 `PowerStrike`, 상태별 Enhanced Input Context 전환과 `WBP_CombatHUD` 연결이 구현됐다. Input Action/Mapping Context와 PlayerController 지정도 완료됐다. HP는 상단 중앙에 유지하고 명령 패널은 `PlayerCommand`에서만 표시한다. 기존 전투의 정상 실행은 사용자 확인을 받았다.

## Milestone 3 — 패링과 회피 (1~2주)

목표: 적 턴에 Telegraph를 읽고 실시간 방어 입력으로 결과를 바꿀 수 있게 한다.

- `EnemyTelegraph`, `EnemyAction`, `DefenseWindow` 연결
- 패링과 회피 입력 및 판정 창 구현
- 성공, 실패, 미입력 결과 적용
- 경계 시간과 중복 입력 테스트
- 판정 결과를 확인할 Debug 표시

완료 기준: 같은 적 공격에 대해 패링, 회피, 피격 결과가 재현 가능하게 구분된다.

Timer 기반 방어 흐름, 패링/회피/실패/미입력 판정과 반격이 구현됐다. `IA_Parry`, `IA_Dodge`, `IMC_DefenseWindow`와 PlayerController 연결은 완료됐으며 E 패링/Q 회피를 사용한다. 방어 버튼은 만들지 않는다. 경계 시간, 무입력 패배, 패링 반격 승리, 중복·재진입 입력과 Timer 도중 참가자 무효화를 자동화 테스트로 검증한다. 방어 결과의 시각 피드백과 Animation Notify 동기화는 연출 단계에서 진행한다.

## Milestone 4 — 몬스터 패턴 데이터화 (1~2주)

목표: 코드 수정 없이 적 공격의 시간과 수치를 교체할 수 있게 한다.

- 스킬 및 몬스터 패턴 Data Asset 구조 확정
- Telegraph, DefenseWindow, 피해량, 타격 횟수 데이터화
- 가중치 기반 패턴 선택의 최소 구현
- 잘못된 데이터에 대한 검증과 안전한 실패 처리
- 테스트용 패턴 1~2개 추가

완료 기준: 서로 다른 패턴 데이터를 같은 실행 흐름에서 사용할 수 있다.

현재 구현 범위는 `UEnemyAttackPatternData`의 단일 타격 패턴과 `CombatantComponent.EnemyAttackPatterns` 목록이다. Coordinator가 적 턴 직전에 유효한 패턴을 가중치로 선택하고 값을 복사하여 실행한다. 빈 목록/전부 무효/전부 가중치 0이면 경고 후 기존 기본 공격을 사용한다. 플레이어 스킬 데이터화, 다단 타격, 방어 불가 정책, 별도 몬스터 프로필, 적응형 AI는 아직 구현하지 않는다.

2026-11-06: Editor Development 빌드와 전투 자동화 테스트 24개 통과. `DA_EnemyBasicAttack` 생성, `BP_PrototypeEnemy` 연결 및 기본 맵에 배치된 적 1개의 상속을 새 명령행 프로세스에서 확인했다. 새 빌드의 PIE 초기 탐험 화면과 정상 종료를 확인했다. 변경 후 조우부터 승리까지의 화면 검증과 사람의 직접 플레이는 아직 완료로 처리하지 않는다.

수동 검증: 기본 에셋에서 피해량 20/예고 1초/방어 0.6초/패링 0.2초를 확인하고 기존 공격·패링·회피·미입력·승리 흐름을 재확인한다. 이어 PIE를 종료하고 피해량 30/예고 2초/방어 0.9초/패링 0.4초로 임시 변경하여 새 PIE에서 반영을 확인한다. 검증 후 기본값으로 되돌려 저장한다. Output Log의 `Enemy pattern selected`에서 선택 ID와 실행 수치를 확인하며 `using BasicAttack fallback` 경고가 없어야 한다. 다중 패턴 선택과 잘못된 데이터 처리는 자동화 테스트로 별도 검증한다.

## Milestone 5 — 전투 연출 연결 (1~2주)

2026-11-07 약한 마법 발사/폭발 분리: 약 1.0초의 왼손 Notify에서 프로젝트 복사본 발사체를 생성하고 적 몸통의 발사 시점 위치까지 이동한 뒤 폭발과 피해 25를 적용한다. 비행과 Montage 완료를 모두 기다리며 중복 발사·피해, 중단·시간 초과·참가자 제거와 Notify 누락을 처리한다. 발사 프레임의 긴 DeltaTime은 비행 계산에서 제외한다. 발사체 복사본의 좌표 공간과 충돌 모듈을 전투 비행 방식에 맞췄으며 원본 팩과 강한 마법은 유지한다. Editor Development 빌드와 전투 테스트 35개가 통과했다. 실제 PIE에서 발사 전 무피해/무폭발, 적 위치 폭발·단일 피해, 직교 방향 발사, 시전 중단의 피해 취소, 느린 비행이 모션보다 길 때 행동 대기, 반복 입력 거부, 다음 턴 복귀와 강한 마법 처치/탐험 복귀를 확인했다. 최종 비행 속도는 DA_BasicMagic에서 500cm/s로 조정했고 캐릭터와 적 사이를 이동하는 불꽃과 도착 폭발을 화면에서 확인했다. 사용자의 직접 플레이로 발사 속도와 폭발 크기의 최종 체감을 확인해야 한다. 조절 방법은 `docs/player-magic-projectile.md`를 참조한다.

목표: 확정된 판정 로직에 Animation, 카메라, VFX, SFX 피드백을 연결한다.

- 플레이어와 적 Animation Montage 연결
- Anim Notify와 판정 시점 동기화
- Telegraph 및 패링/회피 성공 피드백
- 전투 카메라와 최소 화면 전환
- 연출 Event 누락 시에도 전투가 멈추지 않는 대체 경로

완료 기준: 전투 결과를 시각·청각적으로 명확히 이해할 수 있고 연출과 판정이 일치한다.
