# 승리한 조우의 적 제거와 진행 상태

승리 순간에는 적을 유지한다. 3초 슬로모션과 결과창에 마지막 전투 장면을 표시하고, 계속을 확정할 때 적을 Destroy한다. 현재 실행 중 맵을 다시 불러와도 처치한 조우는 완료 상태를 유지한다.

## 처리 순서

1. Coordinator가 Victory와 결과창 준비 상태를 확인하고 중복 확정을 차단한다.
2. 결과창·월드 정지·카메라·모션·Timer·Delegate와 전투 참가자 참조를 정리한다.
3. 해당 조우를 완료 상태로 기록하고 조우 충돌을 비활성화하며 적 참조를 해제한다.
4. 전투에 등록된 적 Actor의 충돌을 끄고 Destroy한다. 플레이어와 아군은 보존한다.
5. 탐험 상태와 입력으로 돌아간다.

이 처리는 승리 결과의 계속 경로에만 있다. 패배 후 재도전/후퇴와 일반 중단 정리에서는 적을 Destroy하거나 조우를 완료하지 않는다. 후퇴한 조우는 기존처럼 다시 들어가 전투할 수 있다.

## 맵 재진입

`UEncounterProgressSubsystem`은 GameInstance에 속하며 맵 패키지 이름과 조우 GUID의 쌍으로 완료 여부를 보관한다. PIE용 패키지 접두사는 제거한다. Actor 포인터·현재 HP·Actor 이름은 완료 기록의 식별자로 사용하지 않는다.

맵이 로드되면 각 BattleEncounterTrigger의 BeginPlay가 기록을 확인한다. 완료된 조우는 배치된 적을 제거하고 조우 충돌을 끄므로 첫 전투로 재진입하지 않는다. 조우 지점 자체는 Tick 없는 비활성 Actor로 남는다. 새 PIE/새 게임 실행은 새로운 GameInstance이므로 적과 조우가 다시 제공된다. 디스크 세이브는 아직 포함하지 않는다.

## 에디터 설정

- Level의 BattleEncounterTrigger를 선택하면 Details → Encounter / Persistence → Encounter Id에서 저장된 GUID를 볼 수 있다.
- 새 조우를 배치하면 ID를 자동 생성하며, 에디터의 복제·붙여넣기는 새 ID를 사용한다. PIE 복제에서는 원래 ID를 유지한다.
- 기존 조우에는 `Tools/SetupEncounterPersistence.py`로 ID를 부여하고 기본 전투 맵을 저장했다. 이 도구는 이미 있는 ID와 전투 수치를 보존한다.
- 조우를 이동하거나 적 외형을 바꿀 때는 같은 ID를 유지한다. 서로 다른 조우에 ID를 수동으로 복사하지 않는다.
- 런타임에 조우를 새로 생성하는 시스템을 추가할 때에는 해당 논리 조우의 고정 ID를 다시 지정해야 맵 이동 후 같은 조우로 인식한다.

`Destroy`는 플레이 중 Actor 인스턴스를 종료하는 처리다. 프로젝트의 적 Blueprint나 맵 배치 원본 에셋을 삭제하지 않는다. 회수는 엔진 GC에 맡기며 전투마다 강제 GC를 호출하지 않는다.

## 검증

2026-11-08: `ExpeditionPortfolioEditor Win64 Development` 빌드와 전투 자동화 테스트 56개 통과. 승리 결과 동안 적 유지, 계속 후 Destroy·충돌 제거·참조 정리, 중복 계속 거절, 플레이어/아군 보존, 완료 조우 재활성화/직접 전투 시작 차단을 검사했다. 세션 기록의 맵·조우 분리, PIE 접두사 정규화, 무효 ID 제외와 새 세션 초기화도 검사했다.

실제 PIE에서 진입 HP 37로 패배→재도전, 다시 패배→후퇴→재조우를 진행해 적과 HP 복원을 확인했다. 승리 결과 배경에 적이 남는 화면을 확인하고 실제 Space로 계속을 확정하여 적 Actor 제거를 확인했다. OpenLevel로 같은 맵을 완전히 재로드한 뒤 동일 GameInstance·조우 GUID·맵 ID·플레이어 HP 37·완료 상태·적 개수 감소를 확인했다. 완료된 조우 영역에 재진입해도 탐험 상태를 유지했으며, 화면에서도 적이 사라진 것을 확인했다. 새 PIE에서 기록 초기화와 적 복귀를 확인한 뒤 진단 콜백과 PIE를 정리했다.

현재 전투 맵의 조우 ID는 저장 완료했다. 사용자의 직접 플레이 최종 확인과 패키징 실행 파일 검증은 남아 있다.
